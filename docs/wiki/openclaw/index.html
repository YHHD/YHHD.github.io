OpenClaw：个人 AI 助手平台架构解析

个人 AI 助手平台的架构、运行原理和扩展边界。

是什么

OpenClaw 是一个运行在个人设备上的 AI Agent 操作系统，将 AI 模型与各种工具连接到日常聊天 App（WhatsApp、Telegram、飞书、钉钉等）。

核心理念：把 AI 助手当作基础设施构建，而不只是优化提示词。 所有会话状态、工具执行、调度逻辑留在自己设备上；AI 模型 API 调用仍走 Anthropic/OpenAI 等服务商。

GitHub：18 万 star，史上增长最快的开源项目之一，核心开发者只有一人。

整体架构

调度中心模式，两大核心模块：

模块 职责
网关 Gateway WebSocket 服务器，连接各聊天平台，将消息派发给 Agent 处理
智能体 Agent 组装上下文、调用 AI 模型、执行工具、保存状态

关键设计思想：消息通信层与 AI 执行层彻底分离。

核心组件

渠道适配器（Channel Adapter）

每个聊天平台一个专属适配器，统一完成四件事：身份验证 → 收消息解析 → 访问控制 → 发消息格式化。

访问控制包括：白名单、私聊策略（配对/开放/禁止）、群聊策略（仅被 @ 时回复）。

Agent 运行时（每轮对话四步）

  1. 会话确定：判断消息所属会话（main / dm:平台:ID / group:平台:ID），会话同时是安全边界
  2. 上下文组装：加载历史记录 + 读取工作空间配置文件 + 语义搜索记忆库
  3. 执行循环：监控模型输出，拦截工具调用请求（命令行/浏览器/文件）并执行，将结果实时回传给模型
  4. 保存状态：把消息和工具调用结果存回磁盘

系统提示词架构

提示词由多个来源动态拼装，不是写死的文件：

  • AGENTS.md：核心规则（能做什么/不能做什么）
  • SOUL.md：人格语气（可选）
  • TOOLS.md：工具备注（可选）
  • 动态上下文：会话历史、相关技能文件、语义搜索到的历史对话
  • 工具定义：内置工具 + 插件工具（自动生成）

智能筛选：只注入当前轮次需要的技能，避免提示词过长导致模型性能下降。

插件系统

四类扩展，放在 extensions/ 目录自动加载，不改核心代码：

插件类型 用途
Channel Plugin 接入新聊天平台
Memory Plugin 替换存储后端（如向量数据库替换 SQLite）
Tool Plugin 添加自定义工具能力
Provider Plugin 接入自定义/本地部署 AI 模型

Canvas / A2UI

AI 驱动的可视化工作区。Agent 生成带特殊标记的 HTML，即可在画布上渲染可交互界面（按钮、列表、表单），用户操作反馈给 AI。独立运行（默认端口 18793），与主网关解耦。

应用场景

  • 自托管 AI 助手，数据完全本地化
  • 多平台统一接入（一个助手同时在 Telegram、WhatsApp、飞书响应）
  • 通过插件扩展 Agent 能力（自定义工具、记忆后端）
  • 手机端将摄像头/录屏/定位能力暴露给 Agent

局限性

  • 一台机器只能跑一个网关（WhatsApp 协议单设备限制）
  • 语音唤醒仅支持 macOS
  • 自托管要求一定运维能力

与其他方案的对比

OpenClaw 普通聊天机器人 Claude Code
运行位置 本地设备 云端 本地终端
接入渠道 多平台聊天 App 单一平台 CLI/IDE
会话状态 本地持久化 云端托管 本地
主要场景 个人 AI 助手基础设施 客服/问答 编程辅助
