重做这个站点：从一页 HTML 到可生长的知识系统

2026年11月12日784 字阅读约 3 分钟
#Astro#设计系统#知识库
目录 · 4 节
参考的是结构，不是皮肤先把设计变成一份契约为什么选 Astro这次交付的边界

旧的 YHHD.github.io 是一份已经生成好的 Hexo 静态产物：没有文章源文件，没有持续维护的构建链，页面里还留着模板占位信息。它能正常打开，但不再适合当作一个长期写作和整理知识的入口。

这次没有在旧主题上继续叠补丁，而是直接换掉整个工程。目标不是“看起来像一个博客”，而是让它同时承担三件事：

  • 一个可以持续写长文的技术博客；
  • 一个按主题组织、可以互链的个人知识库；
  • 一套以后仍然愿意打开、修改和扩展的设计系统。

参考的是结构，不是皮肤

视觉与信息架构参考了青蛙小白的 Wiki：顶部保持轻量导航；知识库使用高密度分组目录；博客流按日期、分类和摘要组织；正文回到约 760px 的阅读宽度。

真正值得保留的是这些阅读体验：

  1. 知识库优先，而不是把所有内容都塞进时间线；
  2. 目录和文章各用一套信息密度；
  3. 极细分割线和高留白建立层级；
  4. 文章页提供目录、阅读时长、标签与前后篇；
  5. 明暗主题和移动端导航保持低干扰。

外观则交给 Notion 风格的设计规范：暖灰纸面、近黑正文、单一蓝色主操作，以及少量只用于标记和装饰的彩色点缀。

先把设计变成一份契约

工程根目录的 DESIGN.md 由下面的命令生成：

npx getdesign@latest add notion

它不是页面脚手架，而是一份供后续开发者和 Agent 共同读取的视觉规则。颜色、字号、间距、圆角和组件边界都先写清楚，再开始写 CSS。这样页面数量增加后，不容易慢慢变成另一套风格。

中文排版没有照抄英文模板的字距参数：大标题保留紧凑字距，正文改用系统中文回退字体和更宽松的 1.7–1.8 行高。

为什么选 Astro

这个站点不需要账号、数据库或服务端渲染。Astro 的静态输出刚好匹配 GitHub Pages：

Markdown 内容
  → Content Collections 校验
  → Astro 静态构建
  → docs/ 静态产物
  → GitHub Pages

博客和知识库使用同一套 frontmatter，但各自维护分类、标签和页面模板。标签页、RSS 和 Sitemap 都在构建时生成，线上没有额外的运行时依赖。

字体通过 npm 本地打包，不依赖 Google Fonts；页面也不接入第三方统计脚本。

这次交付的边界

新站包含：

  • 首页、文章列表与文章详情；
  • 高密度知识库与词条详情；
  • 标签页和关于页面；
  • 明暗主题、移动端导航、代码复制和阅读进度；
  • 代码复制、阅读进度和自动目录；
  • RSS、Sitemap、404 和旧文章 URL 跳转。

它不是一个“上线后什么都不用管”的产品，而是一套可以继续生长的内容工程。后续真正重要的是写什么、如何互相连接，以及如何让旧知识在需要的时候重新被找到。
